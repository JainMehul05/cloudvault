# CloudVault 2.0 test report — 24 November 2026

## Automated checks

34 backend tests passed in 34.84 seconds with the actual cached MiniLM model. Unit/API tests use temporary SQLite and an isolated mocked S3 adapter. They cover the original 24 regressions plus hybrid evidence diversity/scope, citation IDs/exact quotes/relevance, generation response contracts, follow-up/history persistence, explicit fallback, insufficient evidence, invalid scope, stars, migration/vector preservation, safe raster previews, private configuration and cancelled requests not saving exchanges.

10 frontend tests passed. They cover inert HTML/literal highlighting, truthful status/byte displays, REST success/errors and unavailable/damaged local preferences. TypeScript production build, ESLint and Ruff passed. The production initial JavaScript is about 281 kB (87 kB gzip), with a separate approximately 13 kB assistant chunk. npm audit found zero known advisories. Python audit found no known advisories among audited dependencies, but could not audit the CPU-specific torch build; see the raw JSON reports.

## Real AWS checks

AWS_VERIFICATION_V2.json records nine sample originals, including the new water-conservation.txt fixture. Each original matches the real S3 GET and application download bytes; HEAD lengths and AES256 encryption match. Existing bucket/region/public-block settings remain intact. Five predefined semantic cases still rank the expected file first. Exact/hybrid phrase tests and a no-results case passed. Existing user PDF/JPG and object keys remain preserved.

The new fixture was uploaded through the application's real API because Brave's extension refuses automated file selection without broader file-URL permission. Browser navigation, filename filtering and preview of its actual indexed content were verified separately. No extension protection was weakened.

## Actual local generation

LOCAL_AI_INTEGRATION.json distinguishes exploratory/refined runs from the final validated runs. Final validated multi-document and follow-up responses were generated by qwen2.5:3b, using relevant citations from encryption.txt and network-security.txt. Their measured request times were 2.285 and 2.234 seconds; the scoped water-conservation answer took 2.526 seconds. Initial cold loading was much slower: 141.963 seconds including 27.433 seconds retrieval and 114.316 seconds runtime generation/load. Warm results are not a latency guarantee.

During the cold inference test, concurrent health requests had a median 10.27 ms and maximum 252.99 ms. The model reported 100% GPU placement, about 2.3 GB resident size and 6,144 context tokens. Two unrelated/absent-evidence questions abstained. Explicit extractive mode worked. A local-only malicious instruction fixture was ignored and its factual water-conservation answer passed validation. This single fixture is not a proof against all prompt injection.

Concurrent ask returned 409. Explicit cancellation returned 200; the active ask returned 499 and busy became false in 0.19 seconds. Automatic disconnection alone was slower, so the frontend now sends an explicit cancellation token as well as aborting fetch.

## Browser checks

Genuine captures are under screenshots/v2. Verified light/dark overview, files/grid/selection/stars, safe image thumbnail, upload page, search, settings/about, fallback, genuine generated multi-file answer, clicked source preview and natural-language follow-up. Assistant viewport checks at 360, 390, 768, 1024, 1280, 1440 and 1680 pixels showed no horizontal overflow. Overview/upload/search/settings/about at 360 and file grid at 390 also had no horizontal overflow. Native dialogs and labeled controls were inspected. This is focused QA, not a certified WCAG audit.

## Limits

A quotation and semantic relevance check establish evidence provenance/relevance, not guaranteed entailment. A 3B model can misinterpret text. No OCR, public multi-user security, exhaustive corpus summary, cross-encoder reranking or token streaming is claimed. See LIMITATIONS.md and PERFORMANCE_REPORT.md. Historical v1 evidence is preserved under history/v1 and LIVE_VERIFICATION*.json.
